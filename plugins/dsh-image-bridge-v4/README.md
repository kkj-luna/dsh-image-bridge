# 生图桥（@local/image-bridge-v4）

给 **DeepSeek Harness 里没有生图/修图能力的模型**接上外部生图模型。装好并在 Web 设置里配好至少一个模型提供商，模型就获得了 `image_generate`（生图）与 `image_edit`（改图）两个工具。

- **面向用户**：在「设置 → 生图桥」里添加模型提供商（接口地址 + API Key），选中当前使用的那一个。
- **面向模型**：两个工具调用**当前生效服务商**的接口，生成的图片以图片卡片显示在对话里。
- **可以配多个**：每个提供商有自己的地址、密钥与模型；想换厂商，在卡片上点「设为当前」即可。

---

## 一、它解决什么问题

DSH 里的模型能不能作图，取决于模型本身有没有这个能力。本插件把「作图」这件事外包给一个你指定的外部生图模型：

```
用户：帮我画一只戴宇航头盔的柴犬
  └─ 模型调用 image_generate(prompt)
       └─ 插件 → POST {当前生效服务商的接口地址}/images/generations
            └─ 外部生图模型返回图片
                 ├─ 提交为持久图片附件 → 在对话里显示
                 └─ 另存到工作区 generated-images/ → 你随时能打开
```

当前模型不需要有任何视觉能力——**它就是看不见图片，也照样能替你画出来**。

---

## 二、安装

包名用 `@local/` 前缀：这是 DSH 对**本地自作插件**的惯例（表示不发布到 npm），与本机其它本地插件一致。

已经装到 `web` profile 的话可以跳过。重新安装：

在 DSH 会话里让 Agent 执行，或直接用插件管理器把本目录作为本地包安装：

```
plugin_manager  action: install_bundle
                target: <本目录的绝对路径>
```

安装会把这个目录作为 `link:` 依赖写进 profile，并把插件行插入 profile 的配置层（行 id 为 `image-bridge-v4`，同时就是设置页写入的命名空间）。

## 三、配置

「设置 → 生图桥」现在是一张**提供商卡片列表**。每张卡片：

| 元素 | 说明 |
| --- | --- |
| 状态点 | 绿=最近一次「测试」成功，红=失败，灰=还没测过（悬停有文字说明） |
| 名称 | 建卡片时填的名字；留空时显示 id |
| 「当前使用」标签 | 工具实际调用的就是这一家 |
| 生图模型 / 改图模型 | 卡片上直接写出该提供商选用的两个模型；改图为空时显示「沿用生图模型」 |
| 接口地址 | 该提供商的 `baseUrl` |
| 密钥状态 | 已配置 / 未配置（只显示状态，不回显密钥） |
| 按钮 | **测试**、**设为当前**、**编辑**、**删除**（删除是两段式：先点「删除」，再点「确认删除」，或点「取消」） |

列表底部是一个虚线边框的「＋ 添加模型提供商」。点它、或点某张卡片的「编辑」，会打开一个**独立浮层**：半透明遮罩 + 居中面板卡片，标题在左（「添加模型提供商」/「编辑模型提供商」）、右上角是关闭「×」、底部是取消 / 保存。层级取 `z-index: 1200`，稳压宿主自己的浮层（Modal 与图片灯箱 1000、Toast 与挂了 portal 的 Tooltip 1100、菜单 100 / 101）。**关闭有四条路**：右上角关闭、取消、点遮罩、按 Esc。浮层是**额外的一层**——卡片列表与「＋ 添加模型提供商」始终留在原地，打开浮层不会把设置页那棵树卸载重建。

| 字段 / 按钮 | 说明 |
| --- | --- |
| 名称 | 显示名，也是 id 的派生来源 |
| 接口地址 | OpenAI 兼容的基础地址，例如 `https://api.openai.com/v1` |
| API Key | 密码框。**留空表示不修改已保存的密钥**；已保存时提示「已保存密钥」 |
| **测试连接** | 见下。**成功后直接把可用模型列出来**，不用再点第二次 |
| **获取可用模型** | 见下。列表里已经有模型时，按钮文案变成**「重新获取可用模型」** |
| 模型列表 | 「测试连接」成功（或点「重新获取可用模型」）后出现。**默认只列生图模型**，标题写「可用模型（9 / 20）」、下面一行「已隐藏非生图模型： 11」，右侧有「显示全部模型」开关。每行一个模型名，点「生图」或「改图」把它指定给对应角色（同时更新下面两个下拉的选中值），再点一次取消；当前选中的那一行会高亮 |
| 生图模型 / 改图模型 | 两个**下拉选择**，选项就是上面那份列表（「显示全部模型」勾上后连语言模型一起列）。生图的空选项是「未选择」，改图的空选项是「沿用生图模型」。末尾固定一个**「手动输入…」**：选中它才露出文本框，用来填写列表里没有的模型名。还没获取过模型时两个下拉是禁用的，并提示先获取、也可以直接手填 |
| 取消 / 保存 | 保存把 `providers` 与 `activeProviderId` 写进本插件行，密钥写进凭据服务 |

列表下方还有一行**全局默认尺寸**（`size`）：它不属于某个提供商，对所有提供商生效，用自己的「保存尺寸」按钮单独保存。

**测试连接 / 获取可用模型**

两个按钮都先请求本插件在 Host 侧的环回通道（与 `/api` 同一道来源与会话栅栏），由 Host 去问服务商：

- **测试连接** —— `GET {接口地址}/models`，只判断可达性与密钥是否被接受，**不产生生图费用**。成功时 Host 会顺手把这一家的模型列表一起带回来，界面**直接把它列出来**：一次往返就够了，不必再点一次「获取可用模型」。边界行为：
  - 404 算**可达**（该服务可能不提供模型列表，这不影响生图）；401/403 才算密钥问题；500 等其它状态码算**不可达**；
  - 200 但返回体不是合法 JSON、或者没有 `data` 数组 → **仍算可达**，只是没解析出模型（列表为空）——可达性结论绝不受回包格式影响。
- **重新获取可用模型**（列表里还没有模型时显示为「获取可用模型」）—— 单独再拉一次：同样 `GET {接口地址}/models`、`Authorization: Bearer`、**15 秒超时**，只取 `data[].id` 并丢掉空值。非 2xx、非 JSON、没有 `data` 数组都会报错，并把状态码与服务商自述的错误信息一起显示出来——所以「测试连接说 404 可达」而「获取可用模型报 404」都是正常的：这家确实没有可用的 `/models`。拉到的列表在点「保存」后随该提供商一起存进配置，下次打开浮层还在。
- 两条路都没带回模型时，界面会给出接下来该做什么：「测试连接」这条路提示「没取到模型列表，可点「获取可用模型」，或直接填写模型名」；「重新获取可用模型」拿到空列表时提示「接口没有返回可用模型，请直接填写模型名」。

两个按钮都**不会**替你「猜」用哪把密钥：请求里必须显式带上你刚输入的 API Key，或者这张卡片自己的凭据名（`keyRef`）。**两者都没有时 Host 不发出任何网络请求**，直接返回一句可操作提示。这是硬约束，见下面「两条安全约束」。

**默认只显示生图模型**

用户的 Key 实测有 176 个模型，绝大多数是语言 / 向量 / 语音模型，全铺出来等于没有列表。所以列表默认只列判定为生图的那些，规则**刻意做得窄**：

1. 把模型名按非字母数字切成 token，**逐 token 比对**——绝不做整名子串匹配。`qwen-mt-uni`、`qwen3.7-text-embedding-flash`、`glm-5.3` 这类名字里同样有 qwen / text / uni / glm，宽松的正则会成片误判；
2. token 里**含 `image`** 即判为生图：`image`、`imagen`、`imagegen`、`text2image`、`z-image-turbo`、`qwen-image-3.0`、`wan2.7-image` 全覆盖；
3. 再认一组生图专有词：精确命中 `t2i`、`i2i`、`flux`、`kolors`、`dall` / `dalle`、`seedream`、`cogview`、`diffusion`、`sdxl`、`sd3`、`wanx`、`midjourney`、`imagen`；其中 `flux`、`kolors`、`dall`、`seedream`、`cogview`、`sdxl`、`wanx`、`midjourney`、`imagen` 还接受带版本号后缀的写法（`flux1`、`cogview4` 这类）。

列表标题写「可用模型（9 / 20）」，下面一行「已隐藏非生图模型： 11」，右侧是**「显示全部模型」**复选框：勾上就铺开完整列表（一样可以点选）。同一套判定也决定下面两个下拉的选项，所以勾上之后下拉里也能直接选到语言模型。

**「生图模型 / 改图模型」两个下拉**

- **选项来自已获取的模型**（默认只有判定为生图的那批，「显示全部模型」勾上后是全部）；每个下拉末尾固定一个**「手动输入…」**，选中它才露出文本框，用来填列表里没有的名字——手填能力没有丢。
- 生图下拉的空选项是**「未选择」**，改图下拉的空选项是**「沿用生图模型」**（对应契约里 `editModel` 留空即沿用 `imageModel`）。
- **当前值一定出现在选项里**：受控下拉不会因为筛选而显示成空白；**当前已选中的生图 / 改图模型即使不像生图也会保留**，否则用户手填的那个选择会从列表和下拉里一起「消失」。
- **还没获取过模型时**：两个下拉禁用，旁边一行提示「还没有获取到模型列表：先点「测试连接」或「获取可用模型」，也可以直接填写模型名」，并直接进入手动输入——没网、没密钥也能把卡片配完整。
- 下面的模型列表保留为**快捷方式**：点某一行的「生图」/「改图」，上方对应的下拉会同步跳到这个模型（并从「手动输入…」切回来）。两处读写的都是同一个值，**不会出现「下拉显示 A、列表高亮 B」的分裂**。
- 筛选只影响**显示**，不影响保存与生图：列表之外的名字照样可以手填、照样能存下来。

**存到哪里**

- API Key → DSH 凭据服务，落在 `$DSH_HOME/.credentials.yaml`（权限 `0600`）。**不回传浏览器、不写进 profile 的 YAML。**
- 提供商列表与当前使用项（`providers` / `activeProviderId`）、接口地址、模型、尺寸 → 本插件行在 profile 配置层里的字段。这些字段都声明为 `volatile`，所以可以在线改写、无需重启。

**凭据名（keyRef）怎么来的**

每个提供商有自己的凭据名：

```
DSH_IMAGE_BRIDGE_KEY_<ID>        ID = provider.id 转大写、非字母数字一律换成下划线
```

`provider.id` 由名称派生：小写、非 `[a-z0-9]` 折叠成 `-`、去掉首尾 `-`、截断 40 字符（纯中文的名字会折叠成空串，此时改用接口地址的主机名，再不行用 `provider`）；同一列表里重名时追加 `-2`、`-3`…；编辑已有卡片时**保留原 id**，改个显示名不会把密钥甩掉。

**Host 与客户端用同一套规则**（`index.js` 的 `slugifyId` / `providerKeyRef` 与 `client.js` 的 `slugify` / `keyRefOf`）——这是必须的：凭据名由归一后的 id 派生，只要两端归一结果不同，就会出现「界面按 A 名报『密钥未配置』，工具却去 B 名取密钥」。卡片显式声明了合法 `keyRef` 时以它为准；形状不合法（不匹配 `^[A-Za-z_][A-Za-z0-9_]*$`）时两端都忽略并按下 id 推导，客户端还会顺手把非法值改写掉，所以**保存一次即可自愈**。

**升级兼容：旧配置不会看起来「丢了」**

`providers` 为空、而旧的 `baseUrl` / `model` 有值时，设置页会把旧配置合成**一张「现有配置」卡片**（id 为 `default`，凭据名沿用旧的 `DSH_IMAGE_BRIDGE_API_KEY`），工具也仍然走旧字段。编辑并保存这张卡片后，它就变成普通提供商，但凭据名不变——**老的密钥继续有效**。

## 四、行为细节

**当前生效的是哪一个**

三级回退，设置页的「当前使用」标记与工具调用用的是**同一套规则**：

| 级别 | 条件 | 生效对象 |
| --- | --- | --- |
| `active` | `activeProviderId` 命中 `providers` 里的某一项 | 那一项 |
| `first` | 没命中（为空，或指向已被改名/删除的条目）而列表非空 | `providers[0]` |
| `legacy` | `providers` 为空 | 旧的 `baseUrl` / `model` / `editModel`，凭据名 `DSH_IMAGE_BRIDGE_API_KEY` |

一次工具调用取到的参数：`baseUrl` 用该服务商的；生图模型用它的 `imageModel`（为空则回退到旧的 `model`），改图模型用它的 `editModel`（为空则沿用生图模型）；密钥**只在它自己那个凭据名下解析**（先凭据服务，再同名环境变量）。服务商没填接口地址时直接报错，并指出是哪一家。

**两条安全约束（都是有意的）**

1. **没有显式密钥就不发请求。** 「测试连接」「获取可用模型」这两个 RPC 只认请求里显式给出的 `apiKey`，或请求里那个**合法** `keyRef` 指向的凭据；两者都没有时 Host 直接返回失败提示、**一个字节都不往外发**，绝不「退回到当前生效服务商的密钥」。原因是这个回退会真的出事：卡片 A 已存密钥，你新建卡片 B 只填了地址就点测试——第三档回退会把 A 的密钥发到 B 的地址上（凭据外泄），而且 B 的连接状态会被 A 的密钥决定，诊断信息全错。工具调用同理：密钥只在它自己的 ref 下解析，**刻意不跨名字回退**——把 A 的密钥发给 B，远比报一个明确的「缺少密钥」糟糕。
2. **删除提供商不清理凭据。** 删掉一张卡片只会把它从 `providers` 里移除，`$DSH_HOME/.credentials.yaml` 里那个名字对应的密钥**保留**。这是有意为之：删除是配置操作，不该顺手毁掉一份可能要复用的密钥，也不该在用户只是整理列表时做破坏性清理。确实想清掉，就自己从 `.credentials.yaml` 里删掉那一行。

**图片去哪了**

1. 提交为**持久图片附件** —— 对话里以图片卡片呈现，模型（若支持视觉）也能直接看到。
2. 另存为**会话工作区文件** `generated-images/image-<时间戳>-<提示词片段>.png`。目录可以用配置里的 `outputDir` 改，但解析结果必须落在会话工作区内，否则拒绝写入。

**模型看不见图片时会怎样**

工具结果的渲染按**当前调用路由是否声明图片输入能力**分叉：

- 路由声明了 `image` 输入 → 图片作为 image 内容块随工具结果下发，模型直接看到。
- 没有声明（例如纯文本模型）→ 只下发文本信封与文件路径。这是必要的：DSH 的 LLM 适配器会对不支持图片输入的路由抛 `UNSUPPORTED_CONTENT`，硬塞图片会让整个请求失败。

无论哪种情况，**界面上的图片卡片都会显示**——它读的是工具结果里持久化的图片引用，与模型视觉能力无关。

**为什么要有自定义工具卡片**

DSH 内置的富图片卡片在 `dsh-client-ui-tool` 里按工具名硬编码，只认 `read_image`；通用卡片又会把 image 内容块丢掉（`flattenContent` 只取 text）。所以第三方生图结果必须由插件自己注册 `tool.call.toolview` 来渲染。

## 五、排查

先看三份自诊断，它们覆盖了 Host 与浏览器两侧——这个插件几乎所有的失败都能在这里读到原因，不需要靠猜：

| 文件 | 谁写的 | 什么时候有 |
| --- | --- | --- |
| `$DSH_HOME/dsh-image-bridge-startup.json` | Host 半 | **每次激活都覆写**，配置每保存一次也跟着刷新。记录 `apply` 走到哪一步、依赖服务是否就位、生效的配置、**当前在用哪个服务商**、以及失败原因。 |
| `$DSH_HOME/dsh-image-bridge-client.log` | 浏览器半回报 | 页面每次加载或热重载、以及每次「保存 / 测试连接 / 获取可用模型 / 切换 / 删除」都会追加一行（制表符分隔：时间、级别、事件、明细；**绝不记录密钥本身**）。 |
| `$DSH_HOME/dsh-image-bridge-degraded.json` | Host 半 | 仅在依赖解析失败时出现——那意味着没有导出配置 Schema，设置页不会生成。 |

**先看启动自述里的 `provider` 字段：到底在用哪个服务商**

```json
"provider": {
  "level": "active",
  "requested": "zhipu",
  "id": "zhipu",
  "label": "智谱",
  "baseUrl": "https://open.bigmodel.cn/api/paas/v4",
  "keyRef": "DSH_IMAGE_BRIDGE_KEY_ZHIPU",
  "imageModel": "cogview-4",
  "editModel": "cogview-4"
}
```

- `level` 告诉你三级回退**实际落在哪一级**：`active`＝用的就是 `activeProviderId` 指定的那家；`first`＝那个 id 没命中，实际用的是列表第一项（界面也按这条规则纠偏显示）；`legacy`＝没有任何提供商，用的是旧的 `baseUrl` / `model`。
- `baseUrl` / `imageModel` / `editModel` / `keyRef` 是**真正生效**的那一套。只看配置列表分不清「配了」和「真的在用」，这个字段就是为了回答后者。
- 只写凭据名，**没有密钥**。

**客户端日志里与多提供商相关的行**

`配置已载入`（providers 数量、activeProviderId、namespace 是否找到）、`凭据视图`（凭据服务返回的形状，用来确认它到底怎么回答）、`提供商已保存`（id、keyRef、模型数、**keySaved 与 keyLength**，没有密钥）、`提供商已删除`（remaining、keyKept）、`已切换当前提供商`、`默认尺寸已保存`、`编辑浮层已关闭`（mode、id）、`测试连接结果`、`获取可用模型结果`、`凭据引用名不合法，按未配置处理`。

其中两条带着模型规模：`测试连接结果` 里除 ok/message 外还有 `returnedModels`（Host 带回来的模型数）、`imageModels`（其中判为生图的个数）、`adoptedModels`（界面实际采用的个数）——拿着你那把 176 个模型的 Key 一看这三个数，就知道筛选规则是不是按预期工作；`获取可用模型结果` 里同样有 `count` 与 `imageModels`，以及前若干个模型名。卡片上的状态点只反映**本次页面会话内**的测试结果（而且是卡片上的「测试」按钮更新的；浮层里的「测试连接」只把结果显示在浮层里），刷新页面后回到灰色。

**「测试连接 / 获取可用模型」说「没有可用的 API Key」**

这不是网络错误，而是**这张卡片还没有可用密钥**——Host 连请求都没发。两种文案分别对应「这张卡片没填、也没存过密钥」和「这个凭据名（keyRef）下没有密钥」。往输入框里填好、点「保存」再试即可。它与「密钥被拒绝（401/403）」是两回事：后者说明请求真的发出去了、只是服务商不认。

**「测试连接」报密钥被拒绝（401/403）**

密钥不对，或该服务不接受 `Authorization: Bearer` 形式。另注意环境变量优先于凭据服务：多提供商模式下每个服务商读的是**它自己**那个名字的环境变量（例如卡片 id 为 `zhipu` → `DSH_IMAGE_BRIDGE_KEY_ZHIPU`），旧回退模式仍是 `DSH_IMAGE_BRIDGE_API_KEY`。启动 DSH 的 shell 里已经定义了同名环境变量时，凭据服务会拒绝写入（环境变量优先），此时直接用环境变量配置即可。

**报 404**

该服务可能不提供 `/models`，这不影响生图——「测试连接」对 404 会给出软提示（可达，但没有模型）。真正生图时若 404，说明接口路径不是 OpenAI 兼容形态。

**列表或下拉里看不到我要的模型**

默认只显示生图模型（判定规则见「三、配置」）。三条路都行：勾上「显示全部模型」把完整列表铺开（下拉选项也跟着扩展）；或者在「生图模型 / 改图模型」下拉里选**「手动输入…」**，直接把名字填进文本框；再或者点「测试连接 / 重新获取可用模型」重新拉一次列表。筛选只影响显示，不影响保存与调用。

**设置里没有「生图桥」这一页**

1. 插件是否启用：插件管理器里看 `@local/image-bridge-v4` 这一行。
2. 看 `dsh-image-bridge-client.log` 里最近一次 `client apply` 是否报 `fatal`——浏览器侧的问题只会在那里出现。
3. 改动过插件代码？**Node 会缓存已加载的模块，而 DSH 的热重载默认忽略 `node_modules`**，所以运行中的进程仍在用旧代码。重启一次 DSH 服务即可。
4. 看有没有 `dsh-image-bridge-degraded.json`：一旦出现，说明插件没能解析到 `@deepseek-ai/schemastery`，文件里记录了环境事实与每一条解析尝试的失败原因。

**生图失败但没有配置页**

插件在完全没有配置页的情况下仍然可用：工具照常注册。此时可用 profile 的 `cordis.patch.yml` 以旧回退模式提供 `baseUrl` / `model`（密钥用环境变量 `DSH_IMAGE_BRIDGE_API_KEY`），也可以直接写 `providers` + `activeProviderId`，密钥用各自凭据名对应的环境变量。

## 六、实现要点（给维护者）

| 关注点 | 做法与原因 |
| --- | --- |
| 依赖解析 | profile 里的插件目录通常是指向工作区的**链接**，Node 按真实路径解析裸模块名，所以从插件目录出发找不到 profile 或 dsh 安装目录的 `node_modules`。Host 半跨包只依赖 `@deepseek-ai/schemastery`（`Config` 需要它），并按「普通解析 → CLI 入口位置 → `DSH_PROFILE_DIR` → `DSH_HOME` → cwd」逐个基准尝试；全失败则优雅降级并写出自诊断。 |
| 工具定义 | 优先用 `@deepseek-ai/dsh-tools` 的 `defineTool`（带参数校验），解析不到时退化为恒等函数——`ctx.tools.register` 自身仍会校验 `output{schema, render}`。 |
| 图片值结构 | 与内置 `read_image` 完全一致，界面与附件展示插件按同一套字段消费。 |
| 界面与模型分叉 | `output.render` 决定模型看到什么（按视觉能力分叉），`output.presentationMeta` 决定界面看到什么（图片引用恒久化在 `tool/result` 的 meta 上）。 |
| 文件写入边界 | 用 `node:fs` 写工作区文件（`ctx.fs` 没有二进制写入），但写入前强制校验目标目录在会话工作区内。 |
| 设置页读写 | `remote.settings.update('<行 id>', patch, revision)` 要求该行的 Config 字段标记 `volatile()`；`remote.credentials.set(ref, value)` 的 ref 必须是 `^[A-Za-z_][A-Za-z0-9_]*$`。 |
| 多提供商的归一责任 | `provider.id` 的 slug 化必须在两端各做一次、且规则逐字一致（Host `slugifyId` / 客户端 `slugify`）。凭据名由归一后的 id 派生，任一端的归一差异都会造成「两侧不同源」：界面按 A 名报「密钥未配置」，工具却去 B 名取密钥。 |
| 凭据解析不跨名字 | 每个请求只在自己那个 ref 下解析（凭据服务 → 同名环境变量）；RPC 的 `test` / `models` 只认 payload 里的 `apiKey` 或合法 `keyRef`，两者都没有就**不发请求**，杜绝把 A 的密钥发到 B 的地址。 |
| 三级回退只有一套 | `activeProviderId` 命中 → `providers[0]` → 旧字段；设置页的「当前使用」标记与 Host 的 `providerLevelOf` 用同一规则，否则界面说的和实际调用的不是一家。 |
| 模型列表 RPC | `models` 走 `GET {baseUrl}/models`、15 秒超时、只取 `data[].id`；它只是设置页的辅助接口，不能让某个不响应的服务商把设置页卡住。`test` 复用同一份解析（`modelsFromResponse`），解析不出来时只把列表当空，**绝不让回包格式改变可达性结论**。 |
| 浮层实现 | 没有 primitives 就没有 portal 可用，浮层用 `position:fixed` 就地铺满视口，层级取 1200（宿主 Modal/灯箱 1000、Toast 与 portal Tooltip 1100、菜单 100/101）。令牌照抄宿主 Modal（`--dsw-alias-bg-mask-1` / `--dsw-mask-blur` / `--dsw-radius-panel` / `--dsw-elevation-prominent`）。它是**额外的一层**：卡片列表与「＋ 添加」原地不动，开浮层不会卸载重建设置页那棵树，因此不涉及条件 hook。关闭路径（关闭 / 取消 / 遮罩 / Esc）刻意不受 `disabled`/`busy` 约束——一个关不掉的模态会把整页挡住。 |
| 生图模型筛选 | 按 token 判定（见「三、配置」），不做整名子串匹配：`qwen-mt-uni`、`qwen3.7-text-embedding-flash` 这类语言模型名里同样有 qwen / text / uni，宽松正则会成片误判。当前已选中的模型即使不像生图也保留在列表里，避免手填的选择「消失」。 |
| 模型字段只有一份状态 | 「生图模型 / 改图模型」下拉与下面的模型列表读写的都是 `imageModel` / `editModel`：列表按钮除了写值，还会清掉「手动输入」标记，下拉因此会跟着跳过去。下拉里的**「手动输入…」是一个保留取值**（`__dib_manual__`），**不会被写进配置**——它只负责把文本框露出来。当前值一定会并进选项，否则受控 `<select>` 会显示成空白。 |
| 客户端零依赖 | 客户端产物不导入任何 Harness 客户端包，React 由浏览器模块表提供；颜色只用 `--dsw-alias-*` 主题令牌。 |
| 渲染必须全域可执行 | 宿主对渲染期抛错的插槽条目会**永久弃用**，所以配置页与卡片组件对任何字段缺失都退化成一行文本。 |

## 七、目录

```
dsh-image-bridge-v4/
├── package.json        清单：bundle patch、dsh.client、图标、显示元数据
├── cordis.patch.yml    挂载声明（行 id = 设置页写入的命名空间）
├── index.js            Host 半：两个工具、多提供商解析、附件与落盘、test/models/log 通道、降级自诊断
├── client.js           客户端半：自定义工具卡片 + 设置页（提供商卡片列表 / 独立浮层编辑 / 模型下拉筛选与选择）
├── locale/{zh,en}.json 插件卡片上的显示名与简介
└── icon.svg            插件图标
```

回归测试在仓库的 `.dib-verify/`：Host 端到端（假 ctx + 真 HTTP + 真 PNG 字节比对）、客户端注册与组件、清单与跨文件一致性、依赖解析健壮性、跨进程端到端，以及一个可选的本地模拟生图接口。
